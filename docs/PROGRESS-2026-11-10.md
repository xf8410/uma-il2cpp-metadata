## 1. `remove-tp2`（删 `libtersafe2.so`）——CI 成功、真机秒退、路线判死

- run `42825125086`，job `129860331514`，success；产物 `builds/no-tp-1110-1331.apk`
- 250,338,742 B，sha256 `27c5088933a79cc43ee7ce93d3b1658d33a51e5f7c0a541f4a28c5f1bf961dc5`
- 逐 entry 核对：6795 → 6793，**除 META-INF 外所有 entry 名称+CRC 与原包一致**，只少了
  `lib/arm64-v8a/libtersafe2.so` 和 `lib/armeabi-v7a/libtersafe2.so`
- 体积账：两条 libtersafe2 压缩共 3,605,968 B，成品只小 1,511,586 B —— 因为 `remove_entry.py`
  用 Python zipfile 把每个 entry 重写了一遍（默认 level 6 重 deflate），其它 .so 压缩体积涨了约 2.09 MB；
  entry 内容 CRC 不变，语义仍是"只删了 libtersafe2"
- **真机：点开立刻闪回桌面**（不是 1~12 秒的静默 SIGKILL）
- 原因（静态可证，不依赖 logcat）：
  - `libtprt.so`（TP 运行时）dynstr 里有 `libtersafe2.so`，但 `DT_NEEDED` 只有
    `liblog/libc/libm/libstdc++/libdl` ⇒ **运行时 dlopen**
  - `libmain.so` 完全不引用 tersafe（只 `libunity.so`/`libil2cpp.so`/`libmain.dbg.so`）
  - `classes3.dex` 有 `Lcom/tencent/tersafe2/TP2Sdk;`，`classes.dex` 有 `"tersafe2"` 字面量
  ⇒ 启动早期 TP 就要把 `libtersafe2.so` 拉起来，删掉必然在 Unity 起来之前崩
- 结论：**「删/换 TP」不可行**。桩（空 ELF）也救不回来 —— libtprt 会调它的 native 接口，
  要桩就得实现全部导出符号，不现实。此路线降级。

## 3. 黑屏定位第一步：smali 2.5.2 写出 dex **035**，而原包是 **037**（真 bug）

- `classes3.dex` 里有 **13 个带代码的接口方法**（Java 8 default method，037 才允许）：
  `Lkotlin/time/TimeSource;`、`Lokhttp3/CookieJar;`、`Lkotlinx/coroutines/flow/SharingStarted;` 等
- 035 规范不允许 ⇒ ART 校验这些类失败

  （校验范围不含 magic，所以实际只改 4 个字节，signature/checksum 值都不变）
- run `42828820716` → `dex-repack037-1110-1355.apk`（257,052,258 B，sha256 `ccd99cc4…`）
- 自检全过：版本 037、checksum/signature 自洽、proto 12431 / field 26977 / method 52823 / class 6543
  与原包一致、**类名零差异**、13 个默认接口方法仍在
- **真机：仍然黑屏** ⇒ dex 版本不是（唯一）原因

## 4. 收敛到的一个变量：**dex 字节一变就黑屏**

| 改动 | 结果 |
|---|---|
| 全量重压 + 换签名，内容零改动（control-repack） | ✅ 能玩 |
| `zip -0` 原位改一个非 dex 文件（v8 `kotlin-tooling-metadata.json`） | ✅ 能玩 |
| 任何 dex 内容改动（dex-inject ×10、repack035、repack037） | ❌ 黑屏 |

注意第 2 行和第 3 行用的是**完全相同的打包链路**（`zip -0` 原位替换 + `zipalign -p -f 4` +
`apksigner` v1/v2/v3），所以打包链路是干净的，变量只剩「dex 的字节变了」。

待分辨的两种可能：

- **(A) ART 装载重组 dex 失败** —— 某个类验证不过，Unity 起不来 → 黑屏（进程不死）
- **(B) TP 对 dex 做静默拦截** —— 和它对 `lib/` 秒杀不同，dex 这边是"放你启动，引擎不干活"

## 6. 顺手修的 CI 坑

- **status 提交会被 push 撞车吞掉**：bot 的 `git push || true` 与人工提交同时推时静默失败，
  仓库里看不到记录（`remove-tp2` 的 status 就是这么丢的，已补写）。现在 `dex-repack-control`
  改成 `git pull --rebase --autostash` 再 push。
- **`zipalign -c -v` 别写进 status**：6800 行，status 文件直接变 500 KB。现在只留 `tail -n 200`。
- **`dex-inject.yml` / `remove-tp.yml` 没有 paths 过滤**：现在任何一次 push 都会各起一个失败 run，
  仓库历史里全是红叉，容易误判。
- **`gh release download` 默认取 latest 是坑**（HANDOVER 里已记），另外 Release 里现在有
  `no-tp-` / `dex-repack-` / `dex-repack037-` 三种产物，装机前务必核 sha256。
