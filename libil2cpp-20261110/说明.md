# libil2cpp 2026-11-10 版

游戏的核心原生库。Unity 把所有 C# 代码编译成的机器码都在这个文件里，IL2CPP 的运行时（GC、反射、类型系统）也在里面。

**配套的 `global-metadata.fixed.dat` 在 `metadata-20261110/`，两个必须一起用。**

## 为什么存成 .gz 而不是原文件

**GitHub 单文件上限 100 MB，解压后 123.66 MiB 超了。**

推不上去，所以原样保留 gz。用之前解一下：

```bash
gzip -dc libil2cpp.so.gz > libil2cpp.so
md5sum libil2cpp.so
# 期望 3f9909afaa1a415840d690d9f69ea7de
```

## 段布局

| 段 | 起始地址 / 文件偏移 | 说明 |
|---|---|---|
| `.text` | `0x01360E50` | 代码段，120,069,688 字节 |
| `.rodata` | `0x05C17190` | 只读数据 |
| `.data.rel.ro` | `0x07292060` | 需要重定位的只读数据 |
| `.data` | `0x076CA4D8` | 可写数据，9,501,648 字节 |

`.text` 起点在 `0x01360E50` —— 前面 19 MB 是 ELF 头、动态链接表和各种节头。**算 RVA 的时候别拿文件偏移当虚拟地址用**，两者在 `.text` 之后是一致的，但 `.data` 段就已经错开了（`.data` 虚拟地址 `0x076CA4D8`，文件偏移 `0x076BA4D8`，差 0x10000）。

## 怎么用

```bash
gzip -dc libil2cpp.so.gz > libil2cpp.so
Il2CppDumper libil2cpp.so ../metadata-20261110/global-metadata.fixed.dat ./output
```

跑完 `output/` 里会有 `dump.cs`（所有类和方法签名）、`script.json`（给 IDA/Ghidra 用的符号脚本）、`stringliteral.json`。

## 一个必须说清的事

**我没法离线证明这个 so 和那份 metadata 是严格同一次构建的。**

我试过拿 metadata 的字符串池去 so 里比对，命中率只有 2.5% —— 但这个数字**不能当不匹配的证据**，因为 so 是 stripped 的，类名方法名本来就大部分不在这边。

真正的验证只有一个办法：实际跑一遍 Il2CppDumper，看能不能完整 dump 出 `dump.cs`、有没有大量「找不到方法」的警告。跑通了才算配对成功。

所以：**第一次用之前先跑一遍验证，别直接拿去改代码。**
