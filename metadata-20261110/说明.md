## 关键：表结构是自定义紧凑布局

不是标准 v27，直接喂 Il2CppDumper 会解错结构：

| 表 | 本 build | 标准 v27 |
|---|---|---|
| typeDefinition | **88 B**（name@+0x00, ns@+0x04, method_count(u16)@+0x40, field_count(u16)@+0x44, token@+0x54） | 108 B |
| methodDefinition | **32 B**（name@+0x00, declType@+0x04, token@+0x14, paramCount=`dword@+0x1C>>16`） | 40~56 B |
| fieldDefinition | 12 B（name@+0x00, typeIndex@+0x04, token@+0x08） | 12 B ✓ |

所有 `*Start` 字段被删掉，起点靠计数前缀和还原。
实测：typeDefinitions 32,080 条、methods 213,983 条、fields 254,055 条，
`Σ method_count = 213,983`、`Σ field_count = 254,055` 与表行数精确吻合。

解析器在本仓 `tools/parse_metadata.py`，解析结果在 `dump/`，自检结果在 `dump_check.txt`。

## 怎么确认这个文件是好的

```bash
# 1. 大小和 md5 对上
ls -l global-metadata.fixed.dat
md5sum global-metadata.fixed.dat

# 2. magic 和版本号对上（前 8 字节）
xxd -l 8 global-metadata.fixed.dat
# 期望：af1b b1fa 1b00 0000  → magic 0xFAB11BAF，version 27

# 3. 最强的一条：跑解析器自检（段连续到文件尾 + 计数和 = 表行数）
python3 tools/parse_metadata.py global-metadata.fixed.dat --check
```

第 3 条会输出 `last sec ends at EOF: True` 和两个 `OK`；这条过了，说明结构真的完整。

## 已知损失

第 0 块 `0x1000 ~ 0x4FFF`（16KB）是另一套高强度加密（不是 0x66 异或），
静态无法还原，对应 `stringLiteral` 第 512~2527 项约 2016 条字面量缺失。
类型/方法/字段全量完好。

## 配套文件

`libil2cpp.so` 不在本仓，在 `xf8410/uma-ref-hub` 的 `raw/so-20261106/`。

**两个文件必须同一次游戏版本**，配错版本解析出来的符号全是乱的。
本 metadata 是 11-10 的，so 是 11-06 的，差 4 天——如果这期间游戏更新过就得重配。

## 代码地址（RVA）还拿不到

metadata 只能给符号，给不了地址。`libil2cpp.so` 本身也加固过：

- `.text` 只有 5 MB，游戏代码在 71 MB 的自定义 `il2cpp` 段（0x43EE0C8）；
- 文件尾部 `.shstrtab` 之后约 467 KB 不属于任何段，是一块 ELF hook payload，
  字符串含 `ELF_HOOK_LoadMetadataFile` / `ELF_HOOK_MetadataCache_Register`。

要拿 RVA 得先处理这两处（或走运行时 dump）。
